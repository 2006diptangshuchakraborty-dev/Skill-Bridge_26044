## 1. Executive Summary

This survey provides a comprehensive architectural and schema analysis of the Skill Bridge platform. The platform operates on a **dual-persistence hybrid architecture**:
1. **PostgreSQL / Neon Serverless with Drizzle ORM** (`db/schema.js`, `db/index.js`, `db/relations.js`, `drizzle.config.js`) for production and relational migrations.
2. **Synchronous In-Memory & Atomic JSON Database Fallback** (`lib/db.js`, `data/db.json`, `data/seed.json`) with a mock Drizzle query builder (`createMockDrizzleDb` in `db/index.js`) for resilient local execution, headless testing, and serverless fallback.
3. **Better Auth Framework** (`lib/auth.js`, `lib/auth-guard.js`, `app/api/auth/[...all]/route.js`) with pre-OAuth cryptographic intent tokens (`signup_intents`), immutable role assignment across `STUDENT`, `INDUSTRY`, `INSTITUTE`, and automated 1:1 role profile provisioning.

To implement **Requirement R1 (Verified Reputation, Rating, Feedback, Trust, and Review System)**, the platform requires extending both the Drizzle PostgreSQL schema and the local JSON DB layer with **10 new rating tables**, custom PostgreSQL enums, strict foreign keys, compound uniqueness constraints, and backwards compatibility adapters for existing entity profiles (`student_profile`, `organization_profile` / `industry`, and `institute`).

## 3. Database Connection, Query, and Migration Mechanics

### 3.1 Dual-Engine Architecture (`db/index.js`)

```
                         ┌─────────────────────────────┐
                         │      Client / API Route     │
                         └──────────────┬──────────────┘
                                        │
                                        ▼
                         ┌─────────────────────────────┐
                         │         db/index.js         │
                         └──────┬───────────────┬──────┘
                                │               │
          DATABASE_URL Valid?   │               │ No / Dummy / Error / USE_MOCK_DB=true
                                ▼               ▼
     ┌────────────────────────────┐   ┌───────────────────────────────┐
     │  Neon Serverless Pool      │   │  Mock Drizzle Query Builder   │
     │  + drizzle-orm/neon-serv   │   │  (select, insert, update,     │
     │  (PostgreSQL Dialect)      │   │   delete, relations, schema)  │
     └────────────────────────────┘   └───────────────┬───────────────┘
                                                      │
                                                      ▼
                                      ┌───────────────────────────────┐
                                      │  lib/db.js (JSON DB Layer)    │
                                      │  - Memory Cache (cachedDb)    │
                                      │  - data/db.json (Atomic IO)   │
                                      │  - data/seed.json (Golden)    │
                                      └───────────────────────────────┘
```

1. **Production Mode (Neon Serverless PostgreSQL)**:
   * When `DATABASE_URL` is present and valid, `db/index.js` creates a `@neondatabase/serverless` `Pool` and binds it with `drizzle(pool, { schema })`.
   * Queries use Drizzle standard query methods (`db.select().from(...)`, `db.insert(...).values(...)`, `db.update(...).set(...)`, `db.query.users.findFirst(...)`).
2. **Mock / Development / Headless Test Mode**:
   * If `DATABASE_URL` is absent, dummy, or fails to connect, `createMockDrizzleDb()` provides an identical Drizzle interface backed by synchronous JSON atomic operations in `lib/db.js`.
   * Atomic file writing is implemented via unique temporary files and POSIX/Windows `fs.renameSync` to prevent file corruption during high concurrency.
3. **Migration Workflow**:
   * Configuration: `drizzle.config.js` pointing to `./db/schema.js` and `./drizzle`.
   * CLI: `npm run db:generate` (`drizzle-kit generate`) generates incremental SQL migrations and snapshots in `./drizzle/`.
   * Push/Deploy: `npm run db:migrate` (`drizzle-kit migrate`) or `npm run db:push` (`drizzle-kit push`).

### 4.1 Detailed Table Schemas

#### 1. `rating_interactions`
Tracks the verified real-world lifecycle event that grants eligibility to rate.
* `id`: `text('id').primaryKey()` (e.g. `rint_01H...`)
* `interactionType`: `ratingInteractionTypeEnum('interaction_type').notNull()` (`APPLICATION_REVIEW`, `INTERVIEW`, `TASK_ASSESSMENT`, `INTERNSHIP`, `JOB`, `COURSE`, `SEMINAR_EVENT`)
* `referenceId`: `text('reference_id').notNull()` (ID of the application, interview, assessment, course, etc.)
* `initiatorType`: `userRoleEnum('initiator_type').notNull()` (`STUDENT`, `INDUSTRY`, `INSTITUTE`)
* `initiatorId`: `text('initiator_id').notNull()` (entity profile ID or user ID)
* `initiatorUserId`: `text('initiator_user_id').references(() => users.id, { onDelete: 'cascade' })`
* `targetType`: `userRoleEnum('target_type').notNull()` (`STUDENT`, `INDUSTRY`, `INSTITUTE`)
* `targetId`: `text('target_id').notNull()` (entity profile ID or user ID)
* `targetUserId`: `text('target_user_id').references(() => users.id, { onDelete: 'cascade' })`
* `status`: `ratingInteractionStatusEnum('status').default('PENDING_REVIEW').notNull()` (`PENDING_REVIEW`, `REVIEWED`, `INTERVIEW_COMPLETED`, `TASK_COMPLETED`, `INTERNSHIP_COMPLETED`, `COURSE_COMPLETED`, `COMPLETED`, `EXPIRED`, `CLOSED`)
* `isBlind`: `boolean('is_blind').default(false).notNull()` (true for 2-way blind reviews like internships)
* `deadline`: `timestamp('deadline', { withTimezone: true, mode: 'date' })`
* `completedAt`: `timestamp('completed_at', { withTimezone: true, mode: 'date' })`
* `metadata`: `jsonb('metadata').default({}).notNull()` (stores opportunity title, department, application status, match score, etc.)
* `createdAt`: `timestamp('created_at', { withTimezone: true, mode: 'date' }).defaultNow().notNull()`
* `updatedAt`: `timestamp('updated_at', { withTimezone: true, mode: 'date' }).defaultNow().notNull()`
* **Indexes**:
  * `index('rating_interactions_ref_idx').on(table.referenceId, table.interactionType)`
  * `index('rating_interactions_target_idx').on(table.targetType, table.targetId)`
  * `index('rating_interactions_initiator_idx').on(table.initiatorType, table.initiatorId)`
  * `index('rating_interactions_status_idx').on(table.status, table.deadline)`

* `publishedAt`: `timestamp('published_at', { withTimezone: true, mode: 'date' })`

## 6. Backwards Compatibility & Integration Requirements

1. **Entity Terminology & Aliasing**:
   * Customer-facing domain must strictly use `STUDENT`, `INDUSTRY`, and `INSTITUTE`.
   * The database table `organization_profile` is aliased as `industry_profile` / `industryProfiles` in Drizzle exports and mock DB handlers to support both legacy tests and new industry rating APIs.
2. **Zero Breaking Changes for Existing DB & Seed**:
   * All existing columns in `user`, `student_profile`, `organization_profile`, `institute`, and `audit_logs` remain unchanged.
   * `studentProfiles` and `organizationProfiles` gain relations in `db/relations.js` pointing to their respective `ratingAggregates` and `ratings`.
3. **Local JSON DB Fallback (`lib/db.js`)**:
   * `getDb()` must initialize default empty arrays for:
     `ratingInteractions`, `ratings`, `ratingCategories`, `ratingCategoryScores`, `ratingResponses`, `ratingReports`, `ratingAppeals`, `ratingAuditLogs`, `ratingAggregates`, `ratingPolicies`.
   * Add dedicated getter/setter and query methods in `lib/db.js` matching the Drizzle schema.
4. **Mock Drizzle Builder (`db/index.js`)**:
   * Expand `createMockDrizzleDb()` to handle all 10 rating tables in `select()`, `insert()`, `update()`, and `delete()`.
5. **Zero-Rating Empty State Preservation**:
   * Profile components and API endpoints must cleanly distinguish between `totalRatingsCount === 0` ("No verified ratings yet") vs an actual computed rating (e.g. `4.5 ★`), never defaulting an unrated profile to `0.0 ★`.
6. **Separation of Concerns**:
   * Profile views must cleanly separate:
     * **Verification Signals** (Identity, Domain KYC, Opportunity Verified).
     * **Objective Skill Verification** (Assessment score 0–100, Levels 1–5 from `verifications`).
     * **Experience Reputation** (1.00–5.00 stars from verified ratings).
